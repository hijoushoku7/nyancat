# Minecraft サーバー状況通知 Discord Bot 要件定義

## 1. 目的

セルフホストしている Minecraft サーバーの稼働状況や接続情報を、Discord から簡単かつ安全に確認できるようにする。

初期リリースではサーバー監視・通知機能を提供する。Discord 上の会話をもとに発言する機能は、プライバシー、安全性、運用方法を整理したうえで後続リリースとして追加する。

## 1.1 確定している前提

- 身内向けの単一 Discord サーバーで利用する
- 監視対象は Minecraft Java Edition の単一サーバーとする
- Discord Bot と Minecraft サーバーは同じマシンで動作させる
- Minecraft の接続先は対象 Discord サーバー内で公開してよい
- Minecraft サーバーと Bot は、マシン再起動後やプロセス異常終了後も自動復旧させる
- 実装言語と Minecraft サーバーソフトウェアは要件確定後に選定する

## 2. 対象範囲

### フェーズ1: サーバー状況 Bot

- Minecraft サーバーのオンライン・オフライン確認
- 現在の参加人数と最大参加人数の表示
- 接続先情報の表示
- 手動での状況確認
- 状態変化時の自動通知
- Bot と監視処理の運用ログ

### フェーズ2: 会話 Bot

- 許可された Discord メッセージを会話用データとして利用
- サーバー内の会話傾向を参考にした発言
- 管理者による有効化、停止、データ削除
- 不適切な出力を抑止する安全機能

### 初期の対象外

- Minecraft サーバーの起動、停止、再起動
- RCON を使ったゲーム内管理操作
- Discord からのホワイトリスト変更
- 複数 Minecraft サーバーの同時監視
- ユーザーの発言を無断で収集・学習すること
- Bot が生成した発言を自動的に再学習すること

## 3. 利用者と権限

| 利用者 | できること |
|---|---|
| 一般ユーザー | サーバー状況と公開が許可された接続情報の確認 |
| Discord 管理者 | 通知先、監視間隔、表示項目、会話機能の設定 |
| Bot 運用者 | Bot の導入、秘密情報の設定、ログ確認、障害対応 |

管理系コマンドは、Discord の管理者権限または設定済みのロールを持つユーザーに限定する。

## 4. 機能要件

### 4.1 サーバー状況確認

一般ユーザーはスラッシュコマンドで最新状況を確認できる。

コマンド例:

- `/mc status`: 稼働状況を表示
- `/mc address`: 接続先を表示
- `/mc players`: 参加人数を表示
- `/mc help`: 利用可能なコマンドを表示

`/mc status` の表示項目:

- オンラインまたはオフライン
- Java Edition または Bedrock Edition
- サーバーバージョン（取得可能な場合）
- 現在の参加人数と最大参加人数
- 応答時間
- 最終確認日時
- 接続先（公開設定の場合のみ）
- MOTD（取得可能な場合）

プレイヤー名は初期設定では表示しない。表示する場合は Minecraft サーバー側の取得可否と、参加者への周知を確認する。

### 4.2 自動監視と通知

- 設定された間隔でサーバー状態を確認する
- オンラインからオフライン、オフラインからオンラインへの状態変化を検知する
- 状態変化が一定回数連続した場合に確定し、指定チャンネルへ通知する
- 同じ状態の通知を連投しない
- Bot 起動直後は現在状態を記録し、原則として障害通知を送らない
- 長時間オフラインの場合の再通知は設定で有効化できる

初期値案:

- 監視間隔: 60秒
- 状態確定: 3回連続で同じ結果
- 再通知: 無効

### 4.3 設定

以下を環境変数または管理者用設定として保持する。

- Discord Bot トークン
- 対象 Discord サーバー ID
- 通知先チャンネル ID
- Minecraft サーバーのホスト名または IP アドレス
- Minecraft サーバーのポート
- Java Edition / Bedrock Edition
- 接続先の公開可否
- 監視間隔
- 状態確定回数
- 管理者ロール

Bot トークンや非公開 IP アドレスなどの秘密情報を、ソースコード、Discord メッセージ、通常ログへ出力しない。

### 4.4 障害時の動作

次の状態を区別して記録する。

- Minecraft サーバーがオフライン
- タイムアウト
- 名前解決またはネットワークエラー
- Bot 内部エラー
- Discord API への送信失敗

ユーザー向けには内部情報を出しすぎず、運用ログには原因調査に必要なエラー種別と発生日時を残す。

### 4.5 会話機能（フェーズ2）

会話機能はサーバー単位で既定無効とし、管理者が明示的に有効化する。

必要な機能:

- 対象チャンネルを許可リストで指定する
- Bot、Webhook、コマンド、削除済みメッセージを学習対象から除外する
- ユーザー単位またはチャンネル単位で収集対象外にできる
- 収集対象であることを対象チャンネルで継続的に確認できる
- 管理者が収集停止、全データ削除、再構築を実行できる
- ユーザー本人が自分のデータの削除を依頼できる
- 発言頻度、対象チャンネル、応答条件を制限できる
- メンションや特定コマンドへの応答を基本とし、無制限な自発発言を避ける
- 個人情報、認証情報、攻撃的表現などを保存・出力しにくくする
- Bot 自身や他 Bot の生成文を学習対象にしない
- 出力停止用の管理者コマンドを用意する

実装方針として、投稿直後にモデルへ逐次学習させる方式は採用しない。許可されたデータを定期的に整形・審査し、検索による文脈参照または承認済みデータによるモデル調整を候補とする。

## 5. 非機能要件

### 可用性

- Bot プロセスが異常終了した場合に自動再起動できる
- Minecraft サーバーが停止していても Bot 自体は利用可能である
- Discord やネットワークの一時障害後に監視を自動再開する

### 性能

- 手動の状況確認には通常3秒以内を目標に応答する
- 同時リクエスト時は短時間キャッシュを利用し、Minecraft サーバーへの問い合わせ集中を防ぐ
- Discord API のレート制限に従う

### セキュリティ

- 秘密情報は環境変数またはシークレット管理機能に保存する
- Bot に付与する Discord 権限は必要最小限にする
- 管理操作には Discord 側の権限チェックを必須とする
- 外部入力をログ、コマンド、問い合わせ先へ渡す際は検証する
- 会話データはサーバーごとに分離する

### プライバシー

- 保存するデータ、目的、保存期間、削除方法を参加者へ明示する
- 会話データは必要最小限のみ保存する
- 保存期間を設定し、期限を過ぎたデータを削除する
- バックアップにも削除・保持期間の方針を適用する
- 学習データを第三者サービスへ送信する場合は、送信先と取扱いを事前に明示する

### 保守性

- 監視、Discord コマンド、通知、設定、会話機能を分離する
- 設定値の妥当性を起動時に検証する
- 主要処理に自動テストを用意する
- ログには日時、重要度、処理種別を含める

## 6. 保存データ

フェーズ1で保存する候補:

- 現在のサーバー状態
- 最終確認日時
- 最終状態変更日時
- 直近の失敗回数
- 通知先などの Bot 設定

フェーズ2で追加する候補:

- Discord サーバー ID、チャンネル ID、ユーザー ID
- 許可されたメッセージ本文または匿名化・加工済み表現
- 投稿日時
- 同意・除外・削除の状態
- データの有効期限

会話本文を保存せず、特徴量や検索用表現だけを保存する案も比較検討する。

## 7. 運用要件

- コンテナまたはサービス管理機能から常駐起動できる
- Minecraft サーバーと Bot を別々のサービスとして管理し、一方の障害が他方の再起動を妨げない
- マシン起動時に両サービスを自動起動する
- プロセス異常終了時は、再起動間隔と回数制限を設けて自動再起動する
- 起動、停止、再起動、ログ確認の手順を文書化する
- 更新前に設定と保存データをバックアップできる
- 死活監視またはヘルスチェックを用意する
- 障害通知先は Minecraft の状態通知先と分離できる

## 8. 受け入れ条件（フェーズ1）

1. `/mc status` でオンライン・オフラインを正しく確認できる
2. オンライン時に参加人数と最終確認日時が表示される
3. 非公開設定時に接続先が一般ユーザーへ表示されない
4. 状態変化が確定したときだけ指定チャンネルへ1回通知される
5. 一時的な1回の問い合わせ失敗ではオフライン通知されない
6. Minecraft サーバー停止中も Bot のヘルプコマンドが応答する
7. Bot トークンや非公開接続情報がログに残らない
8. 権限のないユーザーは設定を変更できない
9. Bot 再起動後も必要な設定と直前状態を復元できる
10. 主要な監視判定と権限判定の自動テストが成功する

## 9. マイルストーン

1. 仕様確定と技術選定
2. Discord Bot の起動とスラッシュコマンド登録
3. Minecraft サーバー状態取得
4. 状態保持、監視、通知
5. 権限、設定、ログ、テスト
6. セルフホスト環境への配置と運用確認
7. 会話機能のプライバシー・安全要件確定
8. 会話機能の小規模な試験導入

## 10. 未確定事項

- サーバーソフトウェアとバージョン
- 状態通知を送るチャンネル
- 参加者名を表示するか
- 監視間隔と通知確定までの時間
- Bot の実装言語
- 設定・状態保存に使うデータベース
- 会話機能で利用可能な外部 API と予算
- 会話データの保存期間
- 会話データ収集への同意方式
- 自発発言を許可するか、呼びかけ時だけ応答するか
