# nyancat MVP 要件定義

## 1. 目的

身内向け Discord サーバーで、新着メッセージの内容に応じて、自宅の Minecraft Java Edition サーバーの接続先や状態を返す。

## 2. 確定事項

- Bot は Go で実装する
- 実行環境は Ubuntu Server とする
- Docker Compose で起動できるようにする
- Discord Bot と Minecraft サーバーは同じ自宅サーバー上で動作する
- Minecraft の接続先となるグローバル IP アドレスは公開してよい
- Discord のスラッシュコマンドは使用しない
- Discord の新着メッセージを監視し、条件に一致した場合だけ応答する
- メッセージや応答履歴は保存しない
- 学習・会話生成機能は MVP に含めない
- 定期監視、自動障害通知、管理画面などの堅牢化機能は MVP に含めない

## 3. 処理概要

1. Bot が Discord の新着メッセージイベントを受信する
2. Bot 自身および他 Bot のメッセージは無視する
3. 対象 Discord サーバーと対象チャンネルからのメッセージか確認する
4. メッセージ本文が設定済みの条件に一致するか確認する
5. 一致した条件に対応する外部 API を呼び出す
6. API の JSON 応答から必要な値だけを取り出す
7. 元メッセージと同じチャンネルへ結果を返信する

## 4. MVP の応答機能

### 4.1 接続先の応答

グローバル IP アドレス取得 API を呼び出して返信する。Minecraft は標準ポート `25565` を使用するが、返信にはポート番号を表示しない。

応答例:

```text
グローバルIP: 203.0.113.10
```

### 4.2 Minecraft サーバー状態の応答

Minecraft Java Edition の状態取得 API にグローバル IP アドレスを渡し、次の情報を返信する。

- オンラインまたはオフライン
- 現在の参加人数
- 最大参加人数
- バージョン

## 5. メッセージ判定

Minecraft を表す語と、接続先または状態を尋ねる語の組み合わせによって判定する。

Minecraft を表す語:

- `マイクラ`
- `Minecraft`
- `MC`
- `鯖`
- `サーバー`

接続先または状態を尋ねる語の例:

- `IP`
- `アドレス`
- `接続先`
- `どこ`
- `オンライン`
- `状態`
- `開いてる`
- `入れる`
- `できる`

判定前に空白と一部の句読点を除去し、英字の大文字と小文字を区別しない。

## 6. 外部 API

候補:

- グローバル IP アドレス取得: ipify
- Minecraft Java Edition 状態取得: mcstatus.io

API にはタイムアウトを設定する。API 呼び出しまたは JSON 解析に失敗した場合は、内部エラーの詳細を公開せず、取得失敗であることだけを返信する。

条件に一致するメッセージを受信するたびに両 API へ問い合わせ、取得結果はキャッシュしない。

## 7. Discord 設定

新着メッセージ本文を判定するため、Discord Developer Portal で Message Content Intent を有効にする。

Bot に必要な権限:

- 対象チャンネルの閲覧
- メッセージの送信

過去メッセージを取得しないため、MVP ではメッセージ履歴の閲覧権限を要求しない。

MVP では管理者権限を付与しない。

## 8. 設定項目

秘密情報はリポジトリへコミットせず、Docker Compose から環境変数として渡す。

| 設定 | 内容 |
|---|---|
| `DISCORD_TOKEN` | Discord Bot トークン |
| `DISCORD_GUILD_ID` | 対象 Discord サーバー ID |
| `PUBLIC_IP_API_URL` | グローバル IP 取得 API |
| `MC_STATUS_API_URL` | Minecraft 状態取得 API |
| `HTTP_TIMEOUT_SECONDS` | 外部 API のタイムアウト秒数 |

## 9. Docker Compose

- Bot 用イメージをマルチステージビルドで作成する
- 実行用イメージには Go のビルド環境を含めない
- `.env` から秘密情報を渡せるようにする
- `.env` は Git の管理対象外とする
- ローカルの保存領域は原則として使用しない
- Minecraft サーバーは既に別で動作しているため、Compose には Bot コンテナだけを含める

MVP では Docker のヘルスチェックや複雑な再試行制御は必須としない。

## 10. MVP 受け入れ条件

1. `docker compose up -d` で Bot を起動できる
2. Bot が指定された Discord サーバーとチャンネルの新着メッセージを受信できる
3. Bot や対象外チャンネルのメッセージには反応しない
4. 対象文章に一致すると、グローバル IP と Minecraft のオンライン状態を返信する
5. Discord Bot トークンがソースコードや Git 管理ファイルに含まれない
6. API 取得に失敗しても Bot が終了しない
7. メッセージ本文や取得結果をデータベース・ファイルへ保存しない

## 11. MVP 対象外

- スラッシュコマンド
- 過去メッセージの取得
- メッセージの永続保存
- 機械学習
- 生成 AI による会話
- 定期的なサーバー監視
- オンライン・オフライン変化の自動通知
- Discord からの Minecraft 起動、停止、再起動
- 複数 Discord サーバーへの導入
- Web 管理画面

## 12. 未確定事項

- 実際の Discord サーバーで、言い回し判定の過不足を確認して調整する
